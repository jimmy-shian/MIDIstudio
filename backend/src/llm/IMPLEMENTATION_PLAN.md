# 作曲計畫實作工作清單

本清單把使用者提出的創作流程轉成可驗收工作。勾選只代表對應程式/文件已完成並經指定驗證；目前狀態以程式碼為準，不以舊文件自稱完成為準。

## A. 架構與創作決策

- [x] **A1 Guideline Book 一級元件**：獨立完整寫作規格、Skill 使用說明及執行時摘要；system prompt 組裝該模組。
- [x] **A2 表達意圖**：模型在操作前定義意圖，局部修改延續工程原方向；意圖推導音樂性格。
- [x] **A3 整體發展**：按指定長度安排段落功能和能量方向，不擅自延長。
- [x] **A4 核心素材及發展**：先建立少量材料，重複並以有限面向變奏。
- [x] **A5 張力、釋放、編曲及演奏化**：在 runtime 指引與完整規格中明列決策方法。

## B. 執行、檢查與修改

- [x] **B1 工程執行入口**：所有 LLM ops 經 `executeCompositionOps`，先驗證再套用。
- [x] **B2 執行限制與 prompt 一致**：程式限制每回合最多 2 個操作、每次 `add_notes` 最多 32 音；system prompt 限 8 次模型呼叫，最後一次保留 Critic 總檢查。
- [x] **B3 Critic 後續迴圈**：每批操作後檢查；最多 7 輪可修改操作，第 8 輪禁用工具、輸出最終審查/摘要。
- [x] **B4 任務適配**：prompt 允許跳過不適用階段；局部任務延續工程方向，不強制加和弦或重設設定。
- [x] **B5 離線模式**：解析指定小節數，使用正確目標調根；明確識別修改任務並避免錯誤寫入和弦。
- [x] **B6 一致性文件**：架構文件區分程式硬驗證與模型審美判斷，並列出限制來源。

## C. 完成驗證

- [x] **C1 後端及共用套件 build/typecheck**：workspace `npm run typecheck` 與 `npm run build` 成功；補充行為 smoke check 驗證超限批次被拒、合法操作可執行、fallback 小節數/調根正確及局部修改不寫入和弦。
- [x] **C2 工作清單逐項審核**：B2/B3 有 engine/agentLoop 程式控制；B4/B5 有 prompt/fallback 分支；Critic 審美仍由模型判斷，文件已明確標示；沒有宣稱由 deterministic code 證明音樂品質。

## 驗收原則

硬限制必須有程式檢查；創作品質可由模型依 Critic 清單判斷。操作數限制、批次大小、agent 輪數、fallback 行為和 prompt 說法必須一致。任何不能由工具/API觀察的品質聲明都要標示為模型判斷，不能宣稱已被程式客觀驗證。
